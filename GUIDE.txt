======================================

Project root:
  cd /Users/subrat/Desktop/Vllm

IMPORTANT
---------

PIPELINE A - BF16 NON-QUANTIZED BASELINE
----------------------------------------
Existing final report:
  pipeline_a/REPORT.md

Existing valid raw results:
  pipeline_a/results/capacity-20260905-nocache/

Existing analysis:
  pipeline_a/analysis/capacity-20260905-nocache/

If intentionally running a new Pipeline A experiment, start the model with prefix
caching disabled, then invoke benchmark.official_runner with the shared matrix.
Never overwrite capacity-20260905-nocache; choose a new output directory.

1. Start the Pipeline A server:
  pipeline_a/scripts/start_model.sh

2. Run the official controlled benchmark in another terminal:
  .venv/bin/python -m benchmark.official_runner \
    --pipeline pipeline_a \
    --base-url http://127.0.0.1:8101 \
    --served-model Qwen/Qwen3-1.7B \
    --model-path models/pipeline_a \
    --output-dir pipeline_a/results/NEW_RUN \
    --metrics-url http://127.0.0.1:8101/metrics \
    --matrix-path benchmark/capacity_matrix.json

3. Stop the Pipeline A server:
  pipeline_a/scripts/stop_model.sh

Offline analysis command for an existing run:
  .venv/bin/python -m benchmark.capacity_analysis \
    --run-dir pipeline_a/results/NEW_RUN \
    --output-dir pipeline_a/analysis/NEW_RUN

PIPELINE B - USER-CONTROLLED PRECISION VARIANTS
------------------------------------------------
Available variants:
  bf16       floating point, no quantization; Pipeline A already covers it
  fp16       floating point, no quantization
  int8_mlx   MLX 8-bit integer weight quantization
  int4_mlx   MLX 4-bit integer weight quantization

ONE-COMMAND SEQUENTIAL OPTION
-----------------------------
This manually started command runs FP16, then INT8, then INT4. For each variant it
performs conversion when required, verification, server start, official benchmark,
server stop, analysis, and finalization. Variants never run concurrently. Any
failure stops the sequence before the next variant.

  pipeline_b/scripts/run_all_variants.sh \
    --batch-id 20260906 \
    --execute \
    --confirm 20260906

Result directories for that example:
  pipeline_b/results/fp16/fp16-20260906/
  pipeline_b/results/int8_mlx/int8_mlx-20260906/
  pipeline_b/results/int4_mlx/int4_mlx-20260906/

Use a new batch ID for every attempt. Existing run and converted-model directories
are never overwritten. This command is long-running and must be started manually.

UNATTENDED RUN ON MAC
---------------------
About 78 GB of free disk space is comfortably sufficient for this experiment.
Connect the Mac to power, leave Terminal open, and use caffeinate so macOS does not
sleep while conversion and benchmarks run. Locking the screen is fine; closing
Terminal, restarting, or shutting down the Mac is not.

  set -o pipefail
  caffeinate -dimsu pipeline_b/scripts/run_all_variants.sh \
    --batch-id 20260906-unattended-1 \
    --execute \
    --confirm 20260906-unattended-1 \
    2>&1 | tee pipeline_b/logs/pipeline-b-20260906-unattended-1.log

Unattended progress log:
  pipeline_b/logs/pipeline-b-20260906-unattended-1.log

Unattended result directories:
  pipeline_b/results/fp16/fp16-20260906-unattended-1/
  pipeline_b/results/int8_mlx/int8_mlx-20260906-unattended-1/
  pipeline_b/results/int4_mlx/int4_mlx-20260906-unattended-1/

The sequence stops on the first conversion, compatibility, server, or benchmark
failure. Inspect that variant's result directory and the progress log before
starting a new run with a fresh batch ID.

Replace VARIANT and RUN_ID in every command. Example values:
  VARIANT=int4_mlx
  RUN_ID=int4-20260906

1. Validate configuration only:
  .venv/bin/python -m pipeline_b.scripts.validate_variant --variant VARIANT

2. Prepare a new isolated run:
  .venv/bin/python -m pipeline_b.scripts.prepare_variant \
    --variant VARIANT --run-id RUN_ID

3A. INT8/INT4 only - preview conversion without running it:
  .venv/bin/python -m pipeline_b.scripts.quantize \
    --variant VARIANT --run-id RUN_ID

3B. INT8/INT4 only - manually execute conversion:
  .venv/bin/python -m pipeline_b.scripts.quantize \
    --variant VARIANT --run-id RUN_ID --execute --confirm RUN_ID

FP16/BF16 skip step 3 because they are not integer quantization.

4. Verify format, metadata, size, and hashes:
  .venv/bin/python -m pipeline_b.scripts.verify_artifacts \
    --variant VARIANT --run-id RUN_ID

5. Start server in terminal 1:
  pipeline_b/scripts/serve_variant.sh VARIANT RUN_ID

6. Run official benchmark in terminal 2 after server reports ready:
  pipeline_b/scripts/benchmark_variant.sh VARIANT RUN_ID

7. Stop server with Ctrl+C after benchmark exits.
   If needed, record a stopped server before retrying:
  .venv/bin/python -m pipeline_b.scripts.mark_state \
    --variant VARIANT --run-id RUN_ID --target serving_stopped

8. Analyze saved results:
  pipeline_b/scripts/analyze_variant.sh VARIANT RUN_ID

9. Finalize structurally complete run:
  .venv/bin/python -m pipeline_b.scripts.finalize_variant \
    --variant VARIANT --run-id RUN_ID

Pipeline B result location:
  pipeline_b/results/VARIANT/RUN_ID/

It contains RUN_STATUS.json, metadata, conversion records, server command,
official benchmark JSON, resource samples, analysis, optional quality, and report.

COMPARE PIPELINE B WITH PIPELINE A
---------------------------------
This command reads saved files only:
  .venv/bin/python -m comparison.compare \
    --baseline pipeline_a/results/capacity-20260905-nocache \
    --variants-root pipeline_b/results \
    --tuning-root pipeline_3/results \
    --output-dir comparison/results/COMPARE_ID

Comparison outputs:
  comparison/results/COMPARE_ID/COMPARISON_REPORT.md
  comparison/results/COMPARE_ID/manifest.json
  comparison/results/COMPARE_ID/tables/
  comparison/results/COMPARE_ID/charts/

Use a new COMPARE_ID every time. The comparison refuses to overwrite an existing
directory. It discovers every completed Pipeline B run and every analyzed Pipeline
C tuning run. Pipeline C tuning summaries are kept separate from full-matrix
Pipeline A/B comparisons because their workloads are not directly interchangeable.

PIPELINE 3 - OFFICIAL VLLM AUTO-TUNING SWEEP
---------------------------------------------
Pipeline 3 accepts Pipeline A, a completed Pipeline B run, or another already
downloaded local model directory that is genuinely compatible with vLLM-Metal.

1A. Prepare from Pipeline A (plan only):
  .venv/bin/python -m pipeline_3.scripts.prepare_tuning \
    --source models/pipeline_a --dtype bfloat16 \
    --tuning-run-id TUNING_RUN_ID

1B. Or prepare from a completed Pipeline B variant:
  .venv/bin/python -m pipeline_3.scripts.prepare_tuning \
    --source pipeline_b/results/VARIANT/RUN_ID \
    --tuning-run-id TUNING_RUN_ID

2. Inspect all official commands without executing:
  pipeline_3/scripts/run_sweep.sh \
    pipeline_3/results/VARIANT/TUNING_RUN_ID --dry-run

3. Manually start the long official vLLM sweep:
  pipeline_3/scripts/run_sweep.sh \
    pipeline_3/results/VARIANT/TUNING_RUN_ID --execute

Resume an interrupted sweep:
  pipeline_3/scripts/run_sweep.sh \
    pipeline_3/results/VARIANT/TUNING_RUN_ID --execute --resume

4. Rank saved official results offline:
  .venv/bin/python -m pipeline_3.scripts.rank_results \
    --tuning-run pipeline_3/results/VARIANT/TUNING_RUN_ID

Pipeline 3 results:
  pipeline_3/results/VARIANT/TUNING_RUN_ID/official_sweep/
  pipeline_3/results/VARIANT/TUNING_RUN_ID/analysis/ranking.csv
  pipeline_3/results/VARIANT/TUNING_RUN_ID/analysis/winner.json
  pipeline_3/results/VARIANT/TUNING_RUN_ID/analysis/REPORT.md

The benchmark exporter reads saved official JSON and resource samples read-only.
Prometheus scrapes it, and Grafana dashboard 'LLM Benchmark Results' displays
latency percentiles, throughput, failures, memory, swap, and KV-cache usage.
It also discovers analyzed Pipeline C runs and displays each tuning candidate's
settings, P95 TTFT/E2E, output throughput, failures, eligibility, and selected
winner. Pipeline C panels remain separate because its exploratory workload is not
the same as the full Pipeline A/B capacity matrix.

Start only observability plus benchmark exporter from workflow directory:
  docker compose up -d prometheus grafana loki promtail tempo phoenix llm-benchmark-exporter

Open Grafana:
  http://localhost:3000

Dashboard folder:
  Employee Support / LLM Benchmark Results

The exporter never launches a model or benchmark and never changes saved results.
